# 涅槃 Nirvana · 算法设计与分析课程评审平台

面向《算法设计与分析》课程的综合评审平台，覆盖**编程题自动评测**、**主观题匿名互评**、
**学习过程分析**与**异常评审检测**四条主线。系统的每条主线都由可分析、可复现的算法支撑，
而不是常规的信息管理功能。

> 大作业要求「体现算法设计、复杂度分析和实验验证」，因此本项目：
> 1. 为 **6 个核心问题**给出了完整建模、伪代码级实现与复杂度证明；
> 2. 内置 **算法实验台**，可在网页上直接运行 5 组对比实验并导出结果；
> 3. 所有实验数据都来自真实运行（真的编译 C++、真的跑最小费用流），而非写死的结论。

## 三、核心算法（重点）

### 1. 评审任务分配：最小费用最大流 + 2-opt 局部搜索

把「每份作业评 k 次、每人工作量上限 c、禁止自评、避免固定互评关系」建成二分图流网络：

```
source --(k, 0)--> 作者 a --(1, w(a,r))--> 评审者 r --(凸费用平行弧)--> sink
```

* **负载均衡**用「c 条容量 1、费用递增的平行弧」实现凸费用，等价于「负担越重边际代价越高」；
* **成对目标**（互为评审、班级分布方差）无法写进线性费用，用 2-opt 局部搜索修正，
  并通过推导得到 **O(1) 的精确增量 Δ**：`ΔF = α·Δprev + 2ρ·Δ互评 + γ·ΔVar`。

复杂度：MCMF `O(F·V·E)`，局部搜索 `O(R²·I)`，空间 `O(V+E)`。
实测（60 人 / k=3 / c=4）：负载基尼系数 0，互为评审 0 对，耗时约 0.5 s。

### 2. 评分聚合：可信度动态加权的 EM 迭代

模型 `rᵢⱼ = sⱼ + bᵢ + εᵢⱼ`，交替估计作业真实分 `sⱼ`、评审者宽严偏差 `bᵢ` 与可信度 `wᵢ`。
关键点是**经验贝叶斯收缩**：`bᵢ ← nᵢ/(nᵢ+λ_b)·mean`，`ṽᵢ ← (nᵢvᵢ + λ_vσ²)/(nᵢ+λ_v)`，
避免「只评过 2-3 份」的评审者权重崩塌。

实测（60 份作业 / 每份 5 评 / 注入 2 名恶意评审）：RMSE **3.61**，算术平均为 **11.63**（降低 69%）。

### 3. 异常评审检测：统计检验 + 稳健离群 + 关系图

残差 z 检验（单次偏离）、偏差显著性检验（长期偏高/偏低）、MAD 稳健离群（异常时长）、
评分标准差与满分率（打分退化）、互评关系图的互惠边与标签传播社区发现（固定互评/抱团）。

实测注入 40 人次异常：精确率 **0.80**，召回率 **0.93**，F1 **0.86**。

### 4. 学生能力与题目难度：1PL/2PL IRT + ELO

1PL（Rasch）联合极大似然 + L2 正则 + 梯度上升；与 ELO 增量更新并列实现。
实验表明小样本课程数据下 **1PL 比 2PL 更稳**（θ 相关系数 0.87 对 0.81）。

### 5. 代码相似度：Winnowing 指纹 + 倒排索引 + 并查集

token 规范化 → k-gram 滚动哈希 → 滑动窗口最小哈希指纹 → 倒排索引累计 → Jaccard → 并查集聚类。
把 O(n²) 两两比对降到近似线性：60 份代码 **9 ms**，变量改名/加注释仍 100% 命中。

### 6. 复杂度自动判定：对数空间最小二乘

对同一程序在多个规模下实测耗时，在对数空间拟合 `{1, log n, n, n log n, n², n³, 2ⁿ}`。
实测：双重循环 → `O(n²)`（经验指数 2.02），归并排序 → `O(n log n)`（1.24）。

## 四、自动评测引擎

* **真实编译运行**：自动探测本机 `g++ / gcc / javac / python`，C++ 标准从 `c++17 → c++14 → c++11` 逐级回退
  （兼容机房里常见的 TDM-GCC 4.9）。
* **判定**：`Accepted / Wrong Answer / Time Limit Exceeded / Runtime Error / Compile Error /
  Memory Limit Exceeded / Output Limit Exceeded`，超时会杀掉整个进程树。
* **计时**：先预热一次，再扣除「空程序基线」（Windows 上 C++ 约 21 ms、Python 约 44 ms），
  取多次运行中位数，避免把进程启动开销算进学生程序的用时。
* **内存**：Windows 用 `GetProcessMemoryInfo` 读峰值工作集，类 Unix 用 `getrusage` 估算。
* **题库自带参考程序**：每题提供正确/超时/错误三种实现，演示数据里的历史提交都是
  **真实可运行的代码**，所以「重测」得到的结果与展示完全一致。

> ⚠️ 教学用途的沙箱，隔离强度弱于生产 OJ（未使用容器 / namespace）。
> 生产部署应替换为 cgroup 或容器隔离；代码里也保留了静态检查提示。

```
算法大作业/
├── run.py                    一键启动
├── backend/

│   ├── judge.py              编译/运行/判定/复杂度实测
│   ├── problem_bank.py       19 道编程题（测试数据生成器 + 三种参考实现）+ 10 道主观题
│   ├── experiments.py        5 组可复现实验
│   ├── verify_templates.py   参考程序校验（真实评测并缓存）
│   └── algo/                 核心算法包
│       ├── flow.py           最小费用最大流（SPFA 连续最短路）
│       ├── assignment.py     互评分配（MCMF + 局部搜索）
│       ├── aggregation.py    评分聚合（6 种方法 + 留一稳定性）
│       ├── anomaly.py        异常检测（统计 + 图算法）

│       ├── similarity.py     Winnowing 指纹
│       └── complexity.py     复杂度拟合
├── frontend/                 零构建前端（原生 ES Module + 手写 SVG 图表）
│   ├── index.html
│   ├── courseware/           导入的授课课件 PDF（按章节命名）
│   ├── css/app.css           设计系统（深浅双主题）
│   └── js/
│       ├── core/             dom / router / store / api / ui / charts / editor
│       ├── pages/            19 个页面
│       └── demo/             静态演示用内存后端
├── docs/                     设计说明、算法与复杂度分析、实验报告、使用手册
├── tools/
│   ├── import_courseware.py  导入授课课件（复制 PDF + 生成清单）
│   ├── extract_pdf_text.py   课件文本抽取（写讲义摘要/出题时用）
│   └── export_demo.py        导出静态演示数据集
└── tests/                    算法单元测试
```

**为什么不用框架？**

* 后端只用标准库：老师/助教 **克隆下来就能跑**，不需要 pip / npm；
* 前端零构建：`frontend/` 直接静态托管（GitHub Pages 也能跑），改完刷新即可；
* 图表全部用 SVG 手写，风格与设计令牌严格一致，也避免了几百 KB 的第三方依赖。

## 八、已知限制与可拓展方向

1. 评测沙箱为教学级，未做容器隔离；生产化应接入 cgroup + seccomp。
2. MCMF 每次增广只能推 1 单位流量，班级规模 > 200 时耗时上升；可用
   「势能 + 阻塞流（Dinic）」把增广轮数从 O(F) 降到 O(V)。
3. 相似度检测基于 token 指纹，对深度重写灵敏度有限；可扩展为 AST 或基于
   程序依赖图的语义相似度。
4. 能力估计目前是离线批处理；可加入在线 ELO/贝叶斯更新，实现提交后即时刷新。
5. 可拓展：题库自动推荐（按知识点掌握度）、学习预警（连续多次 TLE/WA 触发提醒）、
   评审者反向监督（用聚合结果反查评审质量）。
