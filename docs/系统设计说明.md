# 系统设计说明

## 1. 设计目标与约束

| 目标 | 具体设计决策 |
| --- | --- |
| 老师/助教「克隆下来就能跑」 | 后端只用 Python 标准库（sqlite3 / http.server / subprocess），无 pip 依赖 |
| 前端零构建、可直接静态托管 | 原生 ES Module + 手写 CSS 设计系统 + 自研 SVG 图表，无 npm 依赖 |
| 核心算法必须可复现、可对比 | 算法全部独立成包，实验台通过统一接口调用，结果可导出 JSON |
| 演示数据必须真实 | 历史提交的代码是真实可编译运行的参考程序，判定结果来自真实评测缓存 |
| 匿名互评必须真正匿名 | 服务端对评审者只返回稳定匿名编号；作者身份仅在教师视角可见 |
| 结果公布必须公平 | 评审截止时间之前，学生侧接口直接返回空结果，不依赖前端隐藏 |

```
                │ fetch /api/*   (JSON, Bearer Token)

│  ├─ db.py             SQLite 存储层（WAL、JSON 列）           │
│  ├─ judge.py          编译 · 运行 · 限时限内存 · 复杂度实测    │

        g++ / gcc / javac+java / python
```

## 3. 数据模型

采用 **SQLite + JSON 列** 的混合建模：关系型部分保证一致性查询，
复杂的嵌套结构（评分细则、测试点、算法中间量）存为 JSON 文本，避免为每个小结构建表。

| 表 | 作用 | 关键字段 |
| --- | --- | --- |
| `users` | 用户（教师/助教/学生） | `role`, `class_name`, `student_no` |
| `courses` / `course_members` | 课程与选课关系 | `invite_code` |
| `classes` | 班级（可增删改，带邀请码） | `course_id`, `name`, `invite_code` |
| `course_members.class_id` | 学生与班级的关联（可为空＝未分班） | 班级变动的权威来源，`users.class_name` 作为展示镜像同步 |
| `knowledge_points` | 知识点（对应授课课件章节） | `chapter`, `description` |
| `problems` | 题目（4 种类型） | `type`, `difficulty`, `topics`, **`chapter`**, `time_limit_ms`, `rubric` |
| `materials` | 课件库（章节 → 课件文件） | `chapter`, `chapter_title`, `filename`, `url`, `pages`, `size_bytes`, `topics` |
| `test_cases` | 编程题测试点 | `input`, `expected`, `is_sample`, `score` |
| `assignments` / `assignment_problems` | 作业与组题 | `peer_review`, `reviews_per_submission`, `max_load`, `aggregation_method` |
| `submissions` / `test_results` | 提交与逐测试点结果 | `verdict`, `score`, `time_ms`, `memory_kb`, `detail`(JSON) |
| `subjective_submissions` | 主观题提交 | `content`(JSON 分节), `final_score`, `methods`(各聚合方法得分) |
| `allocations` | 互评分配 | `author_id`, `reviewer_id`, `weight`, `status` |
| `reviews` | 评审记录 | `scores`(JSON 维度分), `total`, `comment`, `duration_sec` |
| `anomalies` | 异常记录 | `type`, `level`, `evidence`, `status`, `handled_by` |
| `events` | 学习行为日志 | `type`, `payload`, `created_at` |
| `experiments` | 实验历史 | `name`, `params`, `result`, `elapsed_ms` |

**索引**：`submissions(problem_id)`、`submissions(user_id)`、`allocations(assignment_id)`、
`reviews(assignment_id)`、`events(user_id)`——覆盖了全部高频查询路径。

## 4. REST 接口设计

共 50+ 个接口，按模块划分，统一返回 `{ok, data}` 或 `{ok:false, error}`。

| 模块 | 代表性接口 |
| --- | --- |
| 认证 | `POST /api/auth/login`、`GET /api/auth/me` |
| 题库 | `GET/POST /api/problems`、`GET/PUT/DELETE /api/problems/{id}` |
| 作业 | `GET/POST /api/assignments`、`GET /api/assignments/{id}` |
| 评测 | `POST /api/submissions`（提交并评测）、`POST /api/run`（只跑样例）、`POST /api/submissions/{id}/rejudge` |
| 互评 | `POST /api/assignments/{id}/allocate`、`GET /api/reviews/mine`、`GET /api/reviews/task/{id}`、`POST /api/reviews/{id}` |
| 聚合与检测 | `POST /api/assignments/{id}/aggregate`、`GET /api/anomalies`、`POST /api/anomalies/{id}/handle` |
| 分析 | `GET /api/analytics/class|problem/{id}|student/{id}|knowledge|ability|timeline` |
| 章节与课件 | `GET /api/chapters`、`GET /api/materials`、`POST /api/materials`（上传）、`PUT/DELETE /api/materials/{id}`、`GET /api/stats/public` |
| 实验 | `GET /api/meta`、`POST /api/experiments/run` |

**权限模型**：路由声明三级可见性——`public`（登录页、元信息）/`user`（需登录）/`teacher`（仅教师与助教）。
分发时统一校验，避免在每个处理函数里重复判断。

**匿名保护**（关键设计）：`GET /api/reviews/task/{id}` 只返回 `匿名#xxxx` 形式的稳定编号；
`GET /api/subjective/{id}` 在学生视角下同样只返回匿名编号，并且在
`review_due_at` 之前把 `final_score` 与全部评审内容清空——**服务端过滤，不是前端隐藏**。

**两类评审对象统一建模**：分配对象既可以是主观题提交，也可以是**代码提交**
（取该学生在这道题上最好的一次提交：`ORDER BY (verdict='Accepted') DESC, score DESC`）。
两者共用同一套分配算法、评分聚合与异常检测流程，只是 `kind`（`text` / `code`）与评分细则不同；
代码互评的聚合分写回 `submissions.review_score` / `review_methods`，
学生只有在自己提交的详情页、且互评截止之后才能看到同学的评价。

### 4.1 以课件章节为主线的知识结构

知识点不是另起一套命名，而是**直接取自实际授课课件的章节结构**，定义在
`backend/courseware.py` 的 `CHAPTERS` 里：

```
Chapter k  →  章节标题  →  知识点名称（topic）  →  该章的课件 PDF 文件
```

由此形成一条贯穿全系统的对齐关系（这也是「题目要根据课件来出」的落地方式）：

| 图层 | 数据来源 | 体现在哪里 |
| --- | --- | --- |
| 课件 | `materials`（PDF 放在 `frontend/courseware/`） | 教师/学生的「课程资源」页按章节浏览、上传、下载 |
| 章节 | `CHAPTERS`（12 个章节，含主题与要点） | `GET /api/chapters` 返回章节 + 课件数 + 题目数 |
| 题库 | `problems.chapter` + `problems.topics` | 题库页按章节筛选；选题器按章节分组 |
| 学情 | `problems.topics` 聚合 | 知识点掌握度、题目难度、薄弱点分析 |

课件 PDF 通过 `tools/import_courseware.py` 导入：脚本按清单把源目录里的 PDF
复制成语义化文件名（`ch05-dynamic-programming.pdf` 之类，避免中文名与空格在 URL
里出问题），记录页数、字节数与 sha256 到 `backend/data/courseware_manifest.json`，
`seed.py` 再依据清单生成 `materials` 记录。这样「课件本体」与「课件元数据」分离：
换一门课只需要改 `courseware.py` 的清单并重跑导入脚本。

## 5. 前端设计

### 5.1 组件层

`core/dom.js` 提供 40 行的 `h(tag, props, children)` hyperscript，
配合 `core/ui.js` 的组件库（卡片、统计块、表格、徽章、弹窗、抽屉、提示、进度条……），
获得接近现代框架的开发体验而无需构建步骤。

`core/charts.js` 用 SVG 实现了 8 种图表：柱状图、折线图、直方图、雷达图、环形图、
散点图（含趋势线）、热力图、二分图弧线图、复杂度双对数图、网络关系图。

`core/editor.js` 实现代码编辑器：透明 `textarea` 叠加高亮层，
支持行号、Tab/Shift+Tab 缩进、回车自动缩进、右括号覆盖输入、C++/C/Python/Java 语法着色。

### 5.2 路由与状态

hash 路由（`#/teacher/analytics`）——静态托管无需服务端 rewrite。
`core/store.js` 管理会话、课程、主题、侧栏折叠状态，持久化到 `localStorage`。
路由守卫统一处理「未登录跳登录页」「已登录访问登录页跳工作台」。

### 5.3 视觉规范

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--brand` | `#0f6b4f` | 主色（松绿），按钮、强调文字 |
| `--brand-2` | `#17a06a` | 渐变终点、成功态 |
| `--ink` / `--muted` | `#0d1b16` / `#7b8f87` | 正文与次要文字 |
| `--surface` / `--line` | `#ffffff` / `#e3ebe7` | 卡片背景与描边 |
| `--radius` | `14px` | 卡片圆角 |
| 侧栏 | `linear-gradient(180deg,#0c1c16,#081310)` | 深色玻璃质感 |

判定结果颜色统一（AC 绿 / WA 红 / TLE 琥珀 / RE 紫），徽章、图表、表格三处保持一致。
深色主题通过 `:root[data-theme="dark"]` 覆盖同一组令牌实现，组件代码零改动。

## 6. 评测引擎设计

```
提交 → 静态检查（提示性质）→ 临时工作目录 → 编译（限时 25s）
     → 逐测试点：写入输入 → 启动子进程（限时 = 题目时限）→ 读取输出
        ├─ 超时 → 杀进程树 → TLE
        ├─ 非零退出 → RE（附 stderr）
        ├─ 峰值内存超限 → MLE
        ├─ 输出超 1MB → OLE
        ├─ token 归一化比较失败 → WA
        └─ 通过 → 累加该测试点分值
     → 汇总：得分 + 最长用时 + 峰值内存 + 逐测试点明细
```

**关键实现细节**

1. **编译器探测**：`g++ -std=c++17/-std=c++14/-std=c++11` 逐级回退（兼容 TDM-GCC 4.9）；
   Java 优先使用与 `javac` 同目录的 `java`（避免 PATH 上版本不一致）。
   另外 Java 有 `mem_multiplier = 2`：JVM 基础开销较大，按主流 OJ 惯例放宽内存限制，
   并用 `-Xmx` 约束堆上界。
2. **计时补偿**：先测「空程序基线」，再从显示耗时中扣除；
   正式测量前预热一次以排除首次磁盘扫描（可达 100 ms）。
3. **资源限制**：`taskkill /F /T`（Windows）或 `killpg(SIGKILL)`（Unix）确保子进程不逃逸。
4. **输出比较**：按 token 切分，忽略行尾空白与多余空行，数值允许 1e-6 相对误差——
   与主流 OJ 的判定标准一致。

## 7. 演示数据生成

`backend/seed.py` 用固定随机种子生成一门完整课程：

* 48 名学生分 2 个教学班，每人有隐藏的「能力值」；
* 10 道编程题 × 4 道主观题，题目元数据与 `problem_bank.py` 共享；
* **384 条提交**：根据学生能力与题目难度选择 `正确 / 超时 / 有 bug` 三种参考实现之一，
  判定结果取自 `verify_templates.py` 的真实评测缓存，因而「重测」结果与展示完全一致；
* **271 份互评**：用真实的最小费用流分配，评分由「作业真实质量 + 评审者偏差 + 噪声」生成，
  并注入 5 类异常（长期偏高、长期偏低、全部满分、无区分度、互为高分、秒评）；
* 1483 条学习行为事件、课程通知、知识点掌握度所需的全部原始数据。

## 9. 安全与隐私

1. 口令使用 PBKDF2-HMAC-SHA256（60 000 次迭代）+ 随机盐，`hmac.compare_digest` 定时安全比较；
2. 所有 SQL 走参数绑定；静态文件服务做了目录穿越校验；
3. 前端所有用户输入经 `esc()` 转义后再进入 HTML；
4. 评测引擎是**教学级**沙箱，未做容器隔离，生产环境必须替换；
5. 互评匿名性由服务端保证，学生侧接口在评审截止前不返回任何评审内容。
