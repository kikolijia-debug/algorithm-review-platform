# 使用手册

## 1. 启动

```bash
python run.py                  # 默认 127.0.0.1:8000
python run.py 0.0.0.0 8000     # 允许局域网访问
python run.py --reset          # 重新生成演示数据后再启动
```

首次启动会自动建库并灌入演示数据，控制台会打印演示账号。

## 2. 演示账号

| 角色 | 账号 | 密码 | 能做什么 |
| --- | --- | --- | --- |
| 教师 | `teacher` | `123456` | 全部功能 |
| 助教 | `ta` | `123456` | 与教师相同（用于批改与复核） |

登录页右下角有「演示账号」快捷按钮，点击即可自动填入。

## 3. 教师端操作路径

### 3.1 布置一次编程作业

1. 进入「作业管理」→ 点击「布置新作业」；
2. 填写标题、截止时间，选择若干**编程题**；
3. （可选）打开「启用匿名互评」开关配置互评参数；
4. 保存后回到作业详情即可看到提交进度。

### 3.2 查看与重测提交

1. 「作业管理」→ 点击某次作业的「详情」；
2. 下方「提交记录」表格点击任意一行，右侧抽屉显示逐测试点结果与源码；
3. 在抽屉里点「重测这份提交」，系统会**真实地重新编译运行**并更新判定；
4. 也可以点页面右上角「重测全部提交」（对前 80 条执行）。

### 3.2.1 班级管理

「教学 → 班级管理」可以完整地增删改班级：

| 操作 | 说明 |
| --- | --- |
| **新建班级** | 填名称（可加说明），邀请码留空会自动生成；学生注册时填该邀请码会直接进班 |
| **重命名** | 改名后所有学生的「班级」显示字段会同步更新 |
| **成员** | 打开抽屉查看学号/姓名/提交次数/已解决题数；可「移出」单个学生 |
| **添加学生** | 从「未分班」或其它班级里勾选学生批量加入 |
| **删除班级** | 会先让你选择学生去向：① 变为「未分班」（默认）② 先转移到另一个班级——**不会删除任何学生账号** |

顶部的「未分班」统计会实时显示还有多少人没归属班级，方便收尾。

### 3.3 开展一轮匿名互评

1. 进入「评审过程管理」，在下拉框选择目标作业；
2. 在「分配管理」标签页调整参数（分配算法、$k$、$c$、各项惩罚权重、随机种子）；
3. 点「重新分配」，页面会展示覆盖率、负载区间、基尼系数、互为评审对数等指标，
   并用二分图弧线图可视化「作业 → 评审者」的分配；
4. 学生完成互评后，点「对当前结果执行评分聚合」；
5. 切到「评分结果」标签页查看每份作业的最终分与各评审原始分；
   切到「可信度与异常」查看评审者偏差、可信度权重与该作业的异常列表。

> 随机种子固定时结果可复现，便于做实验对比；换种子可以得到等价的另一套分配方案。

### 3.4 复核异常评审

1. 进入「异常评审检测」；
2. 顶部四个卡片是高/中/低风险与待处理数量；
3. 「评审者风险汇总」按风险分排序，风险分 $=\sum$（高 22 / 中 11 / 低 4），$\ge 45$ 为高风险；
4. 异常记录表格每行右侧有「确认 / 排除 / 降权」：
   * **确认**：教师复核后认定确实异常；
   * **排除**：复核后判定为正常（例如小样本导致的误报）；
   * **降权**：把该评审者在所有分配上的权重调到 0.3，后续聚合会自动降低其影响。

### 3.5 运行算法实验

1. 进入「算法实验台」；
2. 左侧选择实验，右侧调整参数（学生人数、评审数、偏差强度等）；
3. 点「运行实验」，结果包含指标对比表、图表、结论文本与原始 JSON；
4. 「复杂度实测与自动拟合」会真的编译运行 C++ 程序，约需 10–20 秒。

## 4. 学生端操作路径

### 4.1 做一道编程题

1. 进入「题库与作业」，点击题目卡片；
2. 左侧阅读题意与样例，右侧选择语言（C++/C/Python/Java）并编写代码；
3. 点「运行样例」先在样例上调试（不计入成绩，不写历史）；
4. 点「提交评测」执行全部测试点，下方显示判定、最长用时、峰值内存与逐测试点结果；
   失败时会给出「第一个失败测试点的期望输出 / 实际输出」对比（非 WA 类判定除外）；
5. 代码会自动保存在浏览器本地，刷新不会丢失（可用「重置模板」恢复）。

判定含义：

| 判定 | 含义与排查建议 |
| --- | --- |
| Accepted | 全部测试点通过 |
| Wrong Answer | 输出与期望不一致，注意边界（$n=1$、全负数、重复元素）与整数溢出 |
| Time Limit Exceeded | 复杂度不达标或死循环，对照题目提示的期望复杂度 |
| Runtime Error | 数组越界、栈溢出（递归过深）、除零、空指针 |
| Compile Error | 查看编译信息，注意 C++ 标准（本机为 C++14） |
| Memory Limit Exceeded | 内存超限，检查是否开了过大的数组 |

> **内存限制说明**：Java 因为 JVM 本身要占用几十 MB，平台按主流 OJ 的惯例
> 把 Java 的内存限制放宽为题目限制的 **2 倍**，并用 `-Xmx` 把堆上界压在限制内。
> 所以同样的代码在 C++ 下可能报 MLE、在 Java 下可能通过，这属于正常的语言差异。

### 4.2 提交主观题

1. 题库中选择算法分析题 / 证明题 / 开放性问答题；
2. 按页面给出的分节（如「伪代码与复杂度推导 / 实验方案 / 适用场景讨论」）逐节作答；
3. 提交后系统会记录，并在互评阶段匿名分配给其他同学。

### 4.3 完成匿名互评

1. 进入「互评中心」，待完成列表里点击「开始评审」；
2. 左侧阅读匿名作者的作答，右侧按评分细则逐项拖动打分并填写文字意见；
3. 提交后可在「已完成」中查看或修改。

互评有两类任务，在同一个「互评中心」里统一处理：

| 类型 | 评审对象 | 评分维度 |
| --- | --- | --- |
| **主观题互评** | 算法设计说明、复杂度分析、证明、开放性问答 | 思路与建模 30 / 复杂度 25 / 正确性 25 / 表达 20 |
| **代码互评** | 同学提交的**代码**（带行号展示、可切换自动换行），并附自动评测结论 | 正确性 35 / 效率与复杂度 25 / 代码清晰度 20 / 健壮性 20 |

> 代码互评页会同时给出这份代码的自动评测结果（AC/TLE/WA、用时、通过测试点数），
> 但它只是参考——评分重点仍然是代码本身的问题与改进空间。
> 教师可以在「题库管理」里为每道题单独配置评分细则。

> 系统会记录你的评审时长。明显过短（秒评）、长期偏高/偏低、单次严重偏离或与某人形成固定互评关系，
> 都会进入异常检测清单并可能被教师复核——这是为了保证互评的公平性。

### 4.4 查看互评结果

进入「我的主观题」：评审截止后可以看到各聚合方法下的得分、最终分、以及匿名的文字意见。
评审截止前为了公平，服务端不会返回任何评审结果。

### 4.5 查看学习报告

进入「学习报告」：知识点掌握度雷达（对比班级平均）、薄弱知识点、提交时间线、
判定分布、互评参与统计、学习行为统计与班级排名，支持打印 / 导出 PDF。

## 5. 常见问题

**Q：页面显示「已切换到内置演示数据模式」？**
A：说明没有检测到后端。请确认已运行 `python run.py`，并用它打印的地址访问。
演示模式是只读的，提交代码/评审会给出提示。

**Q：提交后提示「本机未检测到编译器」？**
A：评测引擎支持 C++ / C / Python / Java，会按顺序探测本机环境。
运行 `python -c "from backend import judge; print(judge.available_languages())"` 查看可用语言。

**Q：想让班里同学一起用？**
A：`python run.py 0.0.0.0 8000`，把控制台打印的局域网地址发给同学；
同学用 `stu1`…`stu48` 之外的新账号可以在登录页点「立即注册」（注册码 `ALGO26`）。

**Q：想重新生成演示数据？**
A：`python run.py --reset`。会清空所有数据并重新生成，结果与之前完全一致（固定随机种子）。

## 6. 换成自己班级的真实数据

系统首次启动会灌入一套**演示数据**（48 名学生 / 14 道题 / 384 条提交），
顶栏会显示「演示数据」角标，点它可以看清哪些是模拟的、哪些是真实算法产出的。

演示数据里哪些是真的、哪些是模拟的：

| 内容 | 性质 | 说明 |
| --- | --- | --- |
| 题目与测试数据 | 真实 | 题目取自课程题库，测试数据由参考程序生成 |
| 提交的代码 | 真实 | 题库中三种真实参考实现（正确 / 超时 / 有 bug） |
| 判定与耗时 | 真实 | 真的编译运行过；教师端「重测」可复现同样结果 |
| 互评评分 | 模拟 | 按「作业真实质量 + 评审者偏差 + 噪声」模型生成 |
| 异常检测 / 统计分析 / 图表 | 真实 | 对上述数据真实运行算法得到 |
| **学生自己提交的代码** | **完全真实** | 与演示数据无关，真实编译运行 |

换成真实班级的两步：

```bash
# 1) 清空演示数据（保留题目题库）
python - <<'EOF'
import sys; sys.path.insert(0, '.')
from backend import db
db.init_db()
conn = db.get_conn()
for t in ("submissions", "test_results", "subjective_submissions", "allocations",
          "reviews", "anomalies", "events", "notices", "assignments",
          "assignment_problems", "experiments", "courses",
          "course_members", "users", "settings"):
    conn.execute("DELETE FROM " + t)
conn.execute("DELETE FROM sqlite_sequence")
conn.commit()
print("已清空，题库 problems / knowledge_points / test_cases 保留")
EOF

# 2) 重启服务，然后到登录页注册教师账号、创建课程、导入学生名单
systemctl restart algorithm-review-platform   # 本地部署则重跑 python run.py
```

清空 `settings` 表后顶栏的「演示数据」角标会自动消失。

学生名单可以直接注册（登录页「立即注册」，邀请码由课程表 `courses.invite_code` 决定），
也可以用 SQL 批量导入 `users` 与 `course_members` 两张表。

**Q：如何把系统挂到公网？**
A：静态部分可直接用 GitHub Pages（见 README 的「在线演示」）；
完整系统建议用 gunicorn + nginx，并把 `backend/judge.py` 替换为容器隔离版本。
