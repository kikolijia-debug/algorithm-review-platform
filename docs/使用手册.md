# 使用手册

## 1. 启动

```bash
python run.py                  # 默认 127.0.0.1:8000
python run.py 0.0.0.0 8000     # 允许局域网访问
python run.py --reset          # 重新生成演示数据后再启动
```

首次启动会自动建库并灌入演示数据，控制台会打印演示账号。

## 2. 演示账号

| 角色 | 账号 | 密码 | 能做什么 |
| --- | --- | --- | --- |
| 教师 | `teacher` | `123456` | 全部功能 |
| 助教 | `ta` | `123456` | 与教师相同（用于批改与复核） |
| 学生 | `stu1` … `stu48` | `123456` | 提交、互评、查看个人报告 |

登录页右下角有「演示账号」快捷按钮，点击即可自动填入。

### 2.1 用自己的班级：从注册到开课（不依赖演示数据）

平台不只跑演示数据：注册新账号后可以完整独立使用，而且**课程之间互不可见**。

1. 登录页点「没有账号？去注册」，选择身份：
   * **教师**：填姓名 / 账号 / 密码 / 课程名称 → 注册后自动创建这门课程并成为课程负责人，
     同时生成课程邀请码，可直接开始建班、出题；
   * **学生**：填姓名 / 账号 / 密码，邀请码可填可不填。填了直接进对应课程或班级；
     没填则先进入「未加入课程」状态，登录后在「学习动态」用邀请码加入。
2. 教师进入「班级与学生」→「新建班级」，拿到班级邀请码；
3. 点班级卡片的「成员」→「添加学生」→「新建学生账号」：
   * 单个新建：填姓名、学号即可（账号默认用学号，密码默认 `123456`）；
   * 批量导入：把名单直接粘进去，每行一个学生，支持 `张三,20260001` 或 `张三 20260001`；
4. 学生用「账号 + 默认密码」登录，或在注册时直接填班级邀请码入班；
5. 教师到「作业与题库」出题（可按章节选题、配置测试数据与评分规则）→ 布置作业 →
   学生在「题库与作业」提交 → 自动评测给出判定与耗时。

> 每个账号只看得到自己**所授 / 所加入**课程的题目、作业、提交、互评、异常与统计。
> 新注册的教师看到的是空工作台（0 班级 / 0 学生 / 0 提交），不会混入演示课程的数据。

## 3. 教师端操作路径

教师端菜单只有 6 项，按「一类工作一个入口」组织。**教学看板不再堆数据**，
它只是一张「功能地图」——六张入口卡片，点进去才是具体页面：

| 菜单 | 里面有什么 |
| --- | --- |
| **教学看板** | 纯入口页：作业与题库 / 班级与学生 / 学情分析 / 评审管理 / 算法实验台 / 课程资源，仅对「待处理异常」显示一个数量角标 |
| **作业与题库** | 标签页：作业（创建/编辑、**作业完成情况**：提交进度、通过人数、均分、互评进度）、题库（按章节筛选与增删改）、课件（按章节浏览/上传） |
| **班级与学生** | 标签页：班级（**班级概览**：人数、平均分、通过率 + 增删改与成员管理 + 课程通知）、提交记录（全班提交、源码、重测） |
| **学情分析** | 标签页：班级总览 / 题目分析 / 知识点掌握 / 提交时间线 / 能力与难度 |
| **评审管理** | 标签页：分配管理 / 评分结果 / 可信度与异常 / 异常复核 / 代码相似度 |
| **算法实验台** | 5 组可复现实验 |
| **课程资源**（学生端也有） | 12 个章节的授课课件，可在线打开/下载，每章可跳到该章题目 |

> 每个子页面右上角都有「← 返回」按钮，面包屑也可以点击回上级。

### 3.1 布置一次编程作业

1. 进入「作业与题库」→「作业」标签 → 点击「布置新作业」；
2. 填写标题、截止时间；在「选择题目（按课程章节）」里先选章节（或直接搜索），
   再勾选题目——列表按 **Chapter 0 ~ Chapter 11** 分组，未对应章节的拓展题会单独成组；
3. （可选）打开「启用匿名互评」开关配置互评参数；
4. 保存后回到作业详情即可看到提交进度。

> **看全班完成情况**：点作业列表里的「详情」，页面会按学生列出
> 完成题数、通过题数、得分（每题取最高分求和）、提交次数与逐题状态圆点；
> 点某一行的「查看具体提交」可以看到这位同学每道题的提交次数、判定、耗时、
> 分数，并直接打开源码与逐测试点结果；主观题还能看到他的作答原文。

### 3.2 查看与重测提交

1. 「作业与题库」→「作业」标签 → 点击某次作业的「详情」；
2. 下方「提交记录」表格点击任意一行，右侧抽屉显示逐测试点结果与源码；
3. 在抽屉里点「重测这份提交」，系统会**真实地重新编译运行**并更新判定；
4. 也可以点页面右上角「重测全部提交」（对前 80 条执行）。

### 3.2.1 班级管理

「班级与学生」→「班级」标签可以完整地增删改班级：

| 操作 | 说明 |
| --- | --- |
| **新建班级** | 填名称（可加说明），邀请码留空会自动生成；学生注册时填该邀请码会直接进班 |
| **重命名** | 改名后所有学生的「班级」显示字段会同步更新 |
| **成员** | 打开抽屉查看学号/姓名/提交次数/已解决题数；可「移出」单个学生 |
| **添加学生** | 从「未分班」或其它班级里勾选学生批量加入 |
| **删除班级** | 会先让你选择学生去向：① 变为「未分班」（默认）② 先转移到另一个班级——**不会删除任何学生账号** |

顶部的「未分班」统计会实时显示还有多少人没归属班级，方便收尾。

### 3.3 开展一轮匿名互评

1. 进入「评审管理」，在下拉框选择目标作业；
2. 在「分配管理」标签页调整参数（分配算法、$k$、$c$、各项惩罚权重、随机种子）；
3. 点「重新分配」，页面会展示覆盖率、负载区间、基尼系数、互为评审对数等指标，
   并用二分图弧线图可视化「作业 → 评审者」的分配；
4. 学生完成互评后，点「对当前结果执行评分聚合」；
5. 切到「评分结果」标签页查看每份作业的最终分与各评审原始分；
   切到「可信度与异常」查看评审者偏差、可信度权重与该作业的异常列表。

> 随机种子固定时结果可复现，便于做实验对比；换种子可以得到等价的另一套分配方案。

### 3.4 复核异常评审

1. 进入「评审管理」→「异常复核」标签（也可以从侧边栏的「评审管理」徽章直接进来）；
2. 顶部四个卡片是高/中/低风险与待处理数量；
3. 「评审者风险汇总」按风险分排序，风险分 $=\sum$（高 22 / 中 11 / 低 4），$\ge 45$ 为高风险；
4. 每条异常记录点「查看详情」，右侧抽屉会列出**这位评审者当时的评审记录**：
   给分、各维度得分、文字意见、评审用时、被评对象与作业名，以及这条异常判定的统计依据
   （偏差、p 值、样本数）；
5. 抽屉底部与表格行右侧都有处理按钮：
   * **确认异常**：弹窗二次确认后记录处理痕迹，并下调该评审者权重；
   * **排除**：弹窗确认后判定为正常（例如小样本导致的误报）；
   * **降权**：弹出输入框，**权重比例由教师自己填**（0.05 ~ 1，默认 0.3），
     确认后写回分配权重，重新执行「评分聚合」即生效。

### 3.4.1 互评分配要先由教师确认再发布

「重新分配」之后，分配结果处于 **待确认** 状态，学生在「互评中心」看不到任何任务：

1. 进入「评审管理」→「分配管理」，顶部会提示「本轮互评分配待你确认」；
2. 下面的「分配明细」按「谁的哪道题」分组列出评审者，点右侧 **调整评审人** 可以
   逐条换人：既能移除某个评审者，也能从下拉里补充新的评审者（禁止自评、
   超出每人工作量上限会被拒绝）；任何改动都会让这一轮重新回到待确认；
3. 确认名单无误后点 **确认并发布**，学生端才会出现评审任务；
4. 需要看整体分布时，展开「查看分配关系图（作者 ↔ 评审者）」即可。

### 3.4.2 看每位评审者给了多少分

「评审管理」→「评分结果」里每份提交都有「谁评的」按钮，点开可以看到
每位评审者的姓名、班级、给分、各维度分数、文字意见、评审用时；
在单个作业的详情页里，「互评结果」表格的「评审明细」是同一个抽屉。

### 3.5 运行算法实验

1. 进入「算法实验台」；
2. 左侧选择实验，右侧调整参数（学生人数、评审数、偏差强度等）；
3. 点「运行实验」，结果包含指标对比表、图表、结论文本与原始 JSON；
4. 「复杂度实测与自动拟合」会真的编译运行 C++ 程序，约需 10–20 秒。

### 3.6 管理课件（课程资源）

1. 「作业与题库」→「课件」标签，或在教学看板点「课程资源」；
2. 每张章节卡片列出该章的课件：页数、体积、要点，以及「打开 / 下载 / 编辑 / 删除」；
3. 点「上传课件」选文件、填标题、选章节即可入库（支持 pdf / ppt(x) / doc(x) / zip / md / txt，单文件 ≤ 60 MB）；
4. 卡片右上角「查看本章题目」会跳到按该章节筛选过的题库。

### 3.7 学情分析里能点开的东西

* **题目分析**标签里每道题的「查看提交情况」会列出**谁交了、交了几次、
  谁还没交**，并可用「看代码」直接打开这位同学最近一次提交；
* **班级总览**的「成绩分布」直接写明分数口径：累计得分 = 每道题取最高分再求和
  （主观题取互评最终得分），满分 = 题目数 × 100；
* **常见错误热点**每一行都可以点开，弹窗会解释这类判定（WA/TLE/RE/MLE…）
  通常由什么原因造成、该怎么处理；
* **学生成绩排名**里点「查看报告」进入的是**这位同学**的学习报告
  （知识点掌握、逐题作答、主观题与互评），而不是登录教师自己的报告；
* **能力与难度**标签顶部说明 IRT 与 ELO 分别用来评价什么、结果怎么读。

> 课件 PDF 是当作静态资源直接下发的，浏览器里点「打开」即在线预览。
> 如果换了课程，改 `backend/courseware.py` 里的章节清单，再跑一次
> `python tools/import_courseware.py <课件目录>` 即可。

## 4. 学生端操作路径

### 4.1 做一道编程题

1. 进入「题库与作业」，点击题目卡片；
2. 左侧阅读题意与样例，右侧选择语言（C++ / C11 / Python 3）并编写代码；
3. 点「运行样例」先在样例上调试（不计入成绩，不写历史）；
4. 点「提交评测」执行全部测试点，下方显示判定、最长用时、峰值内存与逐测试点结果；
   失败时会给出「第一个失败测试点的期望输出 / 实际输出」对比（非 WA 类判定除外）；
5. 代码会自动保存在浏览器本地，刷新不会丢失（可用「重置模板」恢复）。

判定含义：

| 判定 | 含义与排查建议 |
| --- | --- |
| Accepted | 全部测试点通过 |
| Wrong Answer | 输出与期望不一致，注意边界（$n=1$、全负数、重复元素）与整数溢出 |
| Time Limit Exceeded | 复杂度不达标或死循环，对照题目提示的期望复杂度 |
| Runtime Error | 数组越界、栈溢出（递归过深）、除零、空指针 |
| Compile Error | 查看编译信息，注意 C++ 标准（本机为 C++14） |
| Memory Limit Exceeded | 内存超限，检查是否开了过大的数组 |

> **内存限制说明**：题目给出的内存上限对三种语言一视同仁；Python 解释器本身要占用
> 十几 MB，同样的算法在 Python 下可能比 C++ 更早接近上限，这属于正常的语言差异。

### 4.2 提交主观题

1. 题库中选择算法分析题 / 证明题 / 开放性问答题；
2. 按页面给出的分节（如「伪代码与复杂度推导 / 实验方案 / 适用场景讨论」）逐节作答；
3. 提交后系统会记录，并在互评阶段匿名分配给其他同学。

### 4.3 完成匿名互评

1. 进入「互评中心」，待完成列表里点击「开始评审」；
2. 左侧阅读匿名作者的作答，右侧按评分细则逐项拖动打分并填写文字意见；
3. 提交后可在「已完成」中查看或修改。

互评有两类任务，在同一个「互评中心」里统一处理：

| 类型 | 评审对象 | 评分维度 |
| --- | --- | --- |
| **主观题互评** | 算法设计说明、复杂度分析、证明、开放性问答 | 思路与建模 30 / 复杂度 25 / 正确性 25 / 表达 20 |
| **代码互评** | 同学提交的**代码**（带行号展示、可切换自动换行），并附自动评测结论 | 正确性 35 / 效率与复杂度 25 / 代码清晰度 20 / 健壮性 20 |

> 代码互评页会同时给出这份代码的自动评测结果（AC/TLE/WA、用时、通过测试点数），
> 但它只是参考——评分重点仍然是代码本身的问题与改进空间。
> 教师可以在「题库管理」里为每道题单独配置评分细则。

> 系统会记录你的评审时长。明显过短（秒评）、长期偏高/偏低、单次严重偏离或与某人形成固定互评关系，
> 都会进入异常检测清单并可能被教师复核——这是为了保证互评的公平性。

### 4.4 查看互评结果

进入「我的主观题」：评审截止后可以看到各聚合方法下的得分、最终分、以及匿名的文字意见。
评审截止前为了公平，服务端不会返回任何评审结果。

### 4.5 查看学习报告

进入「学习报告」：知识点掌握度雷达（对比班级平均）、薄弱知识点、提交时间线、
判定分布、互评参与统计、学习行为统计与班级排名，支持打印 / 导出 PDF。

## 5. 常见问题

**Q：页面显示「已切换到内置演示数据模式」？**
A：说明没有检测到后端。请确认已运行 `python run.py`，并用它打印的地址访问。
演示模式是只读的，提交代码/评审会给出提示。

**Q：提交后提示「本机未检测到编译器」？**
A：评测引擎支持 C++ / C11 / Python 3，会按顺序探测本机环境。
运行 `python -c "from backend import judge; print(judge.available_languages())"` 查看可用语言。

**Q：想让班里同学一起用？**
A：`python run.py 0.0.0.0 8000`，把控制台打印的局域网地址发给同学；
同学用 `stu1`…`stu48` 之外的新账号可以在登录页点「立即注册」（注册码 `ALGO26`）。

**Q：想重新生成演示数据？**
A：`python run.py --reset`。会清空所有数据并重新生成，结果与之前完全一致（固定随机种子）。

## 6. 换成自己班级的真实数据

系统首次启动会灌入一套**演示数据**（48 名学生 / 14 道题 / 384 条提交），
顶栏会显示「演示数据」角标，点它可以看清哪些是模拟的、哪些是真实算法产出的。

演示数据里哪些是真的、哪些是模拟的：

| 内容 | 性质 | 说明 |
| --- | --- | --- |
| 题目与测试数据 | 真实 | 题目取自课程题库，测试数据由参考程序生成 |
| 提交的代码 | 真实 | 题库中三种真实参考实现（正确 / 超时 / 有 bug） |
| 判定与耗时 | 真实 | 真的编译运行过；教师端「重测」可复现同样结果 |
| 互评评分 | 模拟 | 按「作业真实质量 + 评审者偏差 + 噪声」模型生成 |
| 异常检测 / 统计分析 / 图表 | 真实 | 对上述数据真实运行算法得到 |
| **学生自己提交的代码** | **完全真实** | 与演示数据无关，真实编译运行 |

换成真实班级的两步：

```bash
# 1) 清空演示数据（保留题目题库）
python - <<'EOF'
import sys; sys.path.insert(0, '.')
from backend import db
db.init_db()
conn = db.get_conn()
for t in ("submissions", "test_results", "subjective_submissions", "allocations",
          "reviews", "anomalies", "events", "notices", "assignments",
          "assignment_problems", "experiments", "courses",
          "course_members", "users", "settings"):
    conn.execute("DELETE FROM " + t)
conn.execute("DELETE FROM sqlite_sequence")
conn.commit()
print("已清空，题库 problems / knowledge_points / test_cases 保留")
EOF

# 2) 重启服务，然后到登录页注册教师账号、创建课程、导入学生名单
systemctl restart algorithm-review-platform   # 本地部署则重跑 python run.py
```

清空 `settings` 表后顶栏的「演示数据」角标会自动消失。

学生名单可以直接注册（登录页「立即注册」，邀请码由课程表 `courses.invite_code` 决定），
也可以用 SQL 批量导入 `users` 与 `course_members` 两张表。

**Q：如何把系统挂到公网？**
A：静态部分可直接用 GitHub Pages（见 README 的「在线演示」）；
完整系统建议用 gunicorn + nginx，并把 `backend/judge.py` 替换为容器隔离版本。
